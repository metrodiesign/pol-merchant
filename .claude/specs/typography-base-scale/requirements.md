# ความต้องการ: ปรับสเกลตัวอักษรทั้งระบบ

> Status: approved 2026-09-16 (quick, no gates)

## บริบท

ปรับ design token ของ typography ให้ `text-base` มีค่า `1.25rem` (20px เมื่อ root font size เป็น 16px) เพื่อให้ข้อความภาษาไทยอ่านได้เหมาะสมกับ DB Sathorn X โดยให้ขนาดระดับอื่นและ line-height เรียงต่อเนื่องกัน ไม่กระทบ route, authentication, API หรือพฤติกรรมของ settings อื่น

## REQ-1: ค่า base และสเกลตัวอักษร

**ความต้องการของผู้ใช้:** ในฐานะผู้ใช้ระบบ ฉันต้องการให้ข้อความทั้งระบบมีขนาดพื้นฐาน 1.25rem เพื่ออ่านเนื้อหาได้ชัดเจน

**เกณฑ์การยอมรับ:**

- 1.1 ระบบต้องกำหนด design token `--text-base` เป็น `1.25rem` และมี line-height ที่เหมาะกับข้อความภาษาไทย
- 1.2 ระบบต้องกำหนดสเกล token หลักเป็น `--text-xs: 0.9375rem`, `--text-sm: 1.0625rem`, `--text-base: 1.25rem`, `--text-lg: 1.4375rem`, `--text-xl: 1.6875rem`, `--text-2xl: 1.9375rem`, `--text-3xl: 2.3125rem`, `--text-4xl: 2.8125rem` และ `--text-5xl: 3.375rem`
- 1.3 ระบบต้องทำให้ utility แบบ semantic (`text-body*`, `text-subtitle*`, `text-caption` และ `text-overline`) อ้างอิงสเกลเดียวกับ token หลัก แทนการคงค่าเล็กกว่า base โดยไม่สัมพันธ์กับสเกล
- 1.4 ระบบต้องทำให้ส่วนปฏิทินที่เป็นข้อความใช้ขนาดใหม่อย่างสอดคล้อง โดยยังคงขนาดช่องวันและการจัดวางที่อ่านและกดใช้งานได้
- 1.5 ระบบต้องเลื่อนการใช้งาน utility ตั้งแต่ `text-xl` ขึ้นไปลงหนึ่งระดับ (`text-xl` → `text-lg`, `text-2xl` → `text-xl`, `text-3xl` → `text-2xl`, `text-4xl` → `text-3xl`, `text-5xl` → `text-4xl`) รวม responsive variant โดยไม่ให้การแทนค่าทับซ้อนกัน
- 1.6 ระบบต้องคงการใช้งาน `text-base`, `text-sm`, `text-xs` และ utility ที่เล็กกว่า `text-base` ไว้ตามเดิม

## REQ-2: การตั้งค่าและขอบเขตผลกระทบ

**ความต้องการของผู้ใช้:** ในฐานะผู้ใช้ระบบ ฉันต้องการให้การปรับสเกลเป็นการเปลี่ยนแปลงระดับระบบโดยไม่ทำให้หน้าหรือการตั้งค่าเดิมเสียหาย

**เกณฑ์การยอมรับ:**

- 2.1 ระบบต้องคงการปรับขนาดแบบ `rem` จาก `fontSize` ใน settings provider เพื่อให้ผู้ใช้ปรับขนาดเพิ่มเติมได้ตามเดิม
- 2.2 ระบบต้องไม่เปลี่ยน route, authentication, API, data flow, สี, font family หรือ interaction behavior ที่ไม่เกี่ยวกับ typography
- 2.3 หากหน้าจอหรือส่วนประกอบมีข้อความที่ใช้ token หลัก ระบบต้องให้ข้อความนั้นรับค่า token ใหม่โดยไม่ต้องแก้ class ของทุก component เป็นรายไฟล์

## การตรวจความครบถ้วนแบบย่อ

| หมวด | ผลตรวจ |
|---|---|
| ความขัดแย้งเชิงตรรกะ | ไม่มี — ขนาด base ใหม่และลำดับ scale ระบุเป็นค่าคงที่ชุดเดียว |
| ความกำกวม | ไม่มี — กำหนดค่า token และส่วน semantic ที่ต้องสอดคล้องชัดเจน |
| ข้อจำกัดขัดกัน | ไม่มี — settings เดิมใช้ root `font-size` กับค่า `rem` จึงคงไว้ได้ |
| ช่องว่าง | ปรับ line-height ของ token และ calendar ที่เป็น typography โดยไม่ขยายไปยังขนาด SVG/chart ซึ่งเป็น geometry เฉพาะของกราฟ |
| สมมติฐานที่ไม่ได้ระบุ | root font size เริ่มต้นยังเป็น 16px ทำให้ `1.25rem` เท่ากับ 20px ตามค่าที่ผู้ใช้ระบุ |
