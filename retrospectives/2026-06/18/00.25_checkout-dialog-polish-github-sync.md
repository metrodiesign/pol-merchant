## Lessons Learned

- **Pattern**: reference screenshot มาจาก "หน้าอื่น" (drawer/role page) แต่เป้าหมายคือเอา style
  ไป apply ที่ component ปลายทาง — ยืนยัน WHICH component ก่อนแก้ — **Why**: รอบนี้ตีความผิด แก้
  `role-read-view.tsx` แทน modal ต้อง revert. ถ้า image ไม่ระบุไฟล์ชัด ให้ถาม/ยืนยันก่อน edit
  ไม่เดา (ตรง karpathy: ambiguity → ask).
- **Discovery**: `issue_write` (GitHub MCP) `method=create` รับ `state:"closed"` +
  `state_reason:"completed"` ในคอลเดียว — ปิด issue ตอนสร้างได้เลย ไม่ต้อง create แล้ว update —
  **Why**: ลด round-trip ตอน sync task ที่ done แล้วทั้งชุด.
- **Discovery**: epic body ต้องมี `#NN` ของ sub-issue ในตาราง แต่ number เกิดหลังสร้าง (chicken-egg)
  → สร้าง epic ก่อน (table ไม่มี #) → สร้าง subs (ref epic#) → update epic ใส่ #NN — **Why**:
  /spec-sync-github คุม order นี้; เป็น 2 epic write โดยตั้งใจ ไม่ใช่ bug.
- **Discovery**: `sub_issue_write` ตอบกลับ object epic เต็ม (body + repo + user) ก้อนใหญ่มากต่อ call
  — **Why**: sync 7 task = 7 ก้อนใหญ่ กิน output token; คาดไว้ก่อนว่า sync ชุดใหญ่แพง.
