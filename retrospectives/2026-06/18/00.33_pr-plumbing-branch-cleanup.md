## Lessons Learned

- **Pattern**: push commit เพิ่มเข้า feature branch **หลัง PR ของ branch นั้น merge ไปแล้ว** =
  commit ค้างลอย (ไม่อยู่ใน PR ไหน, ไม่เข้า base). ก่อน `commit + pr` รอบถัดไปบน branch เดิม เช็ก
  `gh pr view <n> --json state` ว่า PR ยัง OPEN; ถ้า MERGED แล้ว commit ใหม่ต้องเปิด **PR ใหม่**
  (หรือ branch ใหม่). — **Why**: รอบนี้ assume PR #26 ยัง open เลย push manifest+retro ตามเข้าไป
  แต่มัน merge ไปแล้ว → 2 commit stranded ต้องตามเปิด PR #35 เก็บ. `gh pr create` ที่บอก "already
  exists" ไม่ได้แปลว่า PR ยังเปิด.
- **Discovery**: destructive-guard hook block `git push origin --delete <branch>` ด้วย "confirm
  with a human first" — ลบ remote branch ทำเองไม่ได้ในเซสชัน, ต้องให้ user รันผ่าน `!` prefix
  หรือกด Delete branch บน GitHub UI. — **Why**: อย่าพยายาม bypass (มี bypass-guard); เสนอทางให้
  user ลบเองแทน.
